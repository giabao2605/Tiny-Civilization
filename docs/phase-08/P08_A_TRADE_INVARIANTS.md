# P08-A finite trade invariants (proposal)

Baseline `main@52a06752c949fe9f1956d304fcd9aec433c6bddb`; post-merge CI [#39717445823](https://github.com/giabao2605/Tiny-Civilization/actions/runs/39717445823) `completed/success`, exact SHA. Review 2026-10-22. Phase 08A preproduction, not production feature acceptance.

Shipments (future, not implemented): stable unique ID, origin/destination IDs, good, positive integer cargo, departure/arrival tick, capacity, status (`inTransit`, `delivered`, `returned`, `failed`) and explicitly owned escrow. Accepted departure atomically debits origin and credits escrow. Successful receipt atomically debits escrow and credits destination **once**. Failed destination/route leaves cargo in tracked escrow pending explicit return or terminal-loss policy; never duplicates or silently destroys it. Repeated commands use stable idempotency key. Insufficient stock/capacity rejects with zero side effects. Two arrivals on the same tick use stable ID ordering. Currency is transferred between existing account holders only; explicit cost sinks/sources documented separately. Conservation tests compare origin+destination+escrow+documented consumption/production. Reject negative/overflow/invalid quantities and unknown owners. Persist transit across save/load. No fake event without committed state change.
